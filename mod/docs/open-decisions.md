# Open decisions (to circle back on)

Nothing here blocks single-player work; items 25 and 26 are what a first two-player test should check. Each item says what is undecided and what I am assuming until you say otherwise.
Items already decided live in `prefix-audit.md` ("Decisions made").

## Decided (numbers kept so other notes still point at them)

- **1. Branch names are internal.** Branches keep an internal id and name (`gamble`, `vigor`, `strength_defense` are working tags) for data and tooling, but the tree UI shows no explicit branch titles.
  (Still avoid anything with "Forge" in a name: it is already a native keyword.)
- **6. The imbue system is removed and this mod is Relic Forge's successor.** Relics stop being a route for any of these effects: the mod adds, grants and changes no relics and leaves the relic pool and reward
  tables alone. My reading of "relics should no longer grant any of the same effects": the old imbued-relic effects live only as perks now. Relic Forge is not meant to run alongside this mod; I have not added a
  manifest conflict check, say if you want one.
- **14. `forge_draw_chance` is one chance:** +50% to draw 1 card per node. The old +25% to draw 2 is dropped; several nodes of the same effect can reproduce it later if wanted.
- **30a. `curse_count_ramp` can stack Intangible.** Each perk applies the whole package including Intangible, as implemented. Balance will come from how many of these perks the tree offers, so no mechanical limit for now.
- **32. Every perk can have a chance (decided).** Chance lives on the perk (default for all its nodes) with an optional per-node override; the node's number is always the amount per success. The 16 effects that are only read, never rolled (see `docs/chance-model.md`), stay at 100% for now; the user will say when to change them. Luck perks only touch perks whose chance is below 100%.
- **34. Another character's perks in a tree are allowed.** A perk marked for one character (`characters` in the effect catalog) can be placed in any tree on purpose; the mod's validator, the exporter, `validate.mjs` and the editor only warn. It still does nothing if that character cannot trigger it (a Shiv or Orb perk without those cards), so those are the ones to place with care.
- **35. Frenzied (`vigor_proc_double`).** Decided: it gives the Vigor-spending perks an extra try on every failed roll (the same thing `proc_reroll` does, but only for them: `vigor_strength_pct`, `_block_pct`, `_energy_pct`, `_regen_pct`, `_vulnerable_pct`, `_weak_pct`), and each Vigor point spent has a 10% chance to deal 1 damage to you. The 10% is the perk's chance and the 1 is its amount, so both are editable. My reading: it is real damage (Block soaks it, it can kill you at 1 HP); it does not touch the turn-end perks (`vigor_unused_*`) or the turn-end conversion; the extra try stacks with `proc_reroll` up to the 5-try limit; Frenzied is no longer a flag, so a second copy would double the damage (it is placed once in the tree).
- **36. Keystones and mechanics (decided).** Immolating's HP loss can kill you. Echoing uses the game's own Replay. All five cost keystones and all 14 character-mechanic perks are now coded with the defaults in item 37.
- **39. Three perks added after the audit.** *Healing* (`turn_heal`, general): restore 1 HP at the start of your turn, 100% by default. *Focal* (`focus_gain_chance`, Defect): when you gain Focus, 25% chance to gain 1 more. *Supply* (`play_copy_chance`, general): when you play a card, 25% chance to add a copy of it to your hand, Ethereal and Exhausting. The 25% chances and amounts are placeholders, set in the editor. Each has one new node per tree (Focal only in Defect), hung off a related perk and tagged `custom`; move them wherever you like. They are listed in `data/audit/added-effects.json` so the handler checks know them.
- **41. A tree can have several start nodes (decided).** Any node of type start is an entry point: it can be taken at any time without a connected node, and still costs a point. The mod already worked this way (`tree.starts` is a list, a refund is only blocked while another node depends on that start); the editor, `validate.mjs` and the exporter used to insist on exactly one and no longer do. Costs and keystone distances are counted from the nearest start.
- **42. Preemptive (`first_turn_draw`) is now a chance perk.** Default 50% to draw 1 extra card on your first turn, per node. It used to add to the opening draw through `ModifyHandDraw`, which previews also call and which cannot roll; it now draws right after the opening hand at the start of turn 1. The hand is the same size. Cornered (`low_hp_draw`) still uses `ModifyHandDraw` and stays at 100%; it can be moved over the same way if you want a chance on it.
- **43. Cash Flow (`combat_gold_reward`, general).** At the end of a combat, a separate Gold reward on the rewards screen: 10 Gold at 100% by default (placeholders, set in the editor). All Cash Flow perks roll on their own and add up into ONE reward entry, which sits next to the game's normal gold, card and potion rewards and is never merged into them. Added through the game's own `TryModifyRewards` hook, the way Amethyst Aubergine adds its gold. Fought-combat rooms only (normal, elite, boss), not events or shops. Each tree got one new node near Plundering, tagged `custom`. Never run in game: that the hook runs once per combat per player (a second call would roll again), that two gold entries show as two buttons, and that the Gold lands in the player's total when taken.
- **30b. `energy_discharge` is per Energy gained, not per event.** Damage is the perk total times the Energy gained, as implemented.
- **29. Chance effects stack past 100%.** The 100% cap is gone from every "% chance, per node" effect (19 of them); on/off effects and resistances keep theirs. Each perk of a chance effect rolls ON ITS OWN, so three +50% perks are three rolls at 50% (about 1.5 procs on average, 12.5% chance of none). A perk whose chance is past 100% (a big node, or `proc_boost` / `proc_double` pushing it over) gives its whole part as sure procs plus a roll for the rest. `proc_reroll` gives the remainder extra tries. Procs per event are capped at 100, only so a runaway stack can't loop forever.
  *My reading of your example.* The other way to read it is one pooled total (150% = one sure proc plus a 50% roll). Same average, but no chance of getting nothing. It is a one-function change (`ChanceMath.RollTotal`) if you prefer it.
  *The "apply 1 more X" perks* (`vulnerable_extra_chance`, `poison_extra_chance`, `doom_extra`) listen for the very thing they add, so each is guarded against re-triggering itself (the extra names the enemy as its own applier, plus a re-entrancy flag), and Discharging won't discharge again while it is discharging. Any new perk of that kind needs the same. Infinite scaling is fine; infinite loops are not.

## Assumptions I made while building (change on request)

10. **Start nodes cost a point** and grant their effect like any other node.
11. **Unspent points carry over** to the next map screen.
12. **Persistence granularity.** Perk state is saved exactly when the game saves its run (room entry, end of combat, event changes), so the two always match
    and a reload cannot be used to re-earn points. Consequence: allocations you make on the map after the last game save revert if you quit before the next
    one. You keep the points, only the choices are redone. Preserving pending choices across a quit as well is possible but needs an award ledger so replays
    cannot double-award; I judged that over-engineered. Say if you want it.

47. **Healthy (`max_hp`, general, added 2026-11-01).** +1 Max HP per node (placeholder number, set in the editor). Like Potion+, it is not a handler: on every room entry the host compares the COMMITTED total with what it has granted so far (saved counter `max_hp.granted`) and applies only the difference. Pending points do nothing, so allocating and refunding on the map cannot be used to heal; the Max HP arrives once, when you enter the room after locking the perks in. Gaining uses the game's own `CreatureCmd.GainMaxHp`, which also heals by that amount, exactly as Strawberry does (say if you want Max HP only, with no heal: it would use `SetMaxHp` instead). A fractional total is rounded down. It always 100%: the chance field is locked. If the committed total ever drops, the same difference is taken off with `LoseMaxHp`, never below 1 Max HP. Not placed in any tree yet. Never run in game: `GainMaxHp` from `AfterRoomEntered` (including entering a combat room), the Max HP surviving a save and reload together with the counter, and the heal showing in the HP bar at once.
48. **Nodes can have their own amount (2026-11-01).** Like the per-node chance, a single node can override the perk's number: Edit mode, side panel, "Amount" (empty = the perk's number; typing the perk's own number clears it). It is saved on the layout node as `amount` and the exporter writes it as that node's `magnitude`. The mod needed no change: tree nodes already carried a magnitude each, `EffectTotals` already adds them, and `RollTotal` already rolls each node with its own amount; handlers only read those totals. Tooltips, totals, the Balance table, cap checks and the luck-perk line in the editor now add up the real amounts (mixed amounts read like "2 perks, mixed amounts at 50% (avg 4.25 Block)"). Rules: not 0; not allowed on on/off perks (the exporter and `validate.mjs` report an error, the editor hides the field); changing a node to another perk clears its chance and amount; copy/paste keeps both. Caveats: a perk whose handler treats its total as a threshold or ratio (Congealing's Block per Vigor, for example) just sums, which is the wanted behaviour there too; perks with a cap clamp the summed total, not each node. Never run in game: nothing new, the mod already read per-node magnitudes (covered by unit tests, now including a mixed-amount `RollTotal` test).

Assumptions: the two reactions count every application once per enemy, so Hidden Dose over three enemies rolls three times; they use the game's "power changed" hook for powers the owner applied to an enemy, the same one Envenomed uses, so Poison from Envenomed's bonus copy (applied with the enemy as its own applier) does not count; they only react to a positive Poison amount, so the end-of-turn Poison tick never counts. Neither can trigger itself (Block and damage apply no Poison). Poison Cloud's damage is Unpowered (Strength and Vulnerable do not scale it) and can kill the enemy. They are in general because Hidden Dose lets any character poison; with no Poison source they simply never fire. None placed in any tree yet. Never run in game: that `AfterPowerAmountChanged` reports Poison from a perk's own `PowerCmd.Apply` with you as the applier, and `CreatureCmd.Damage` on a single target from inside that hook.
50. **Swift Defense (`damaged_block_chance`, general, added 2026-11-01).** When you take damage, each Swift Defense rolls its chance (10%, placeholder) and gives 1 Block (placeholder) straight away. "Take damage" is read as damage that gets past your Block, the same test Centennial Puzzle and Cornered's cousins use (`UnblockedDamage > 0`), so a hit that Block fully absorbs does not count; say if you want every hit to count, it is a one-line change. The Block comes after the hit has landed, so it never softens the hit that triggered it; it helps against the rest of a multi-hit attack and later attackers. Any damage to you counts, including your own perks' (Immolating's start-of-combat HP loss, Frenzied), so those can roll it too. Each perk rolls on its own; Block cannot damage you, so it cannot loop. Not placed in any tree yet. Never run in game: `AfterDamageReceived` reporting `UnblockedDamage` correctly for multi-hit attacks.
